# LogSentry

표준 웹서버 접근 로그(nginx/apache combined)를 읽어 **침입 시도를 탐지·기록**하는 범용 도구.
대상 앱의 코드를 고치지 않는다. 어느 프로젝트든 로그만 있으면 붙는다. 읽기 전용(막기는 다음 단계).

## 왜

AI 기반 자동 공격은 로그인 화면만이 아니라 API·없는 주소를 빠르게·넓게·느리게 쑤신다.
대부분의 서버는 이미 접근 로그를 남긴다. LogSentry 는 그 로그만 읽어, 코드 수정 없이 공격 징후를 찾아낸다.

## 탐지 규칙 (로그로 가능한 것)

| 규칙 | 내용 |
|---|---|
| P1 경로 탐색 | 한 IP 가 없는 주소(404)를 여러 번 |
| P2 인증 두드림 | 한 IP 가 401/403 을 여러 번 |
| P3 과속 | 한 IP 가 짧은 시간에 많은 요청 |
| P4 도구 지문 | User-Agent 가 curl/python/scanner 등 |
| P5 IP 종합 | 위 신호를 IP 로 합산·점수화 (분산·저속 공격) |

계정 단위(스프레이·잠금)는 접근 로그에 계정 정보가 없어 다음 단계(앱 연동)에서 추가한다.

## 사용

```
python logsentry.py access.log
python logsentry.py access.log --window 60 --probe-threshold 5 --score-threshold 6
```

## 예시 결과 (sample_access.log)

```
🔴 45.146.0.99   점수 32 — 없는 주소 10회·탐침경로 10개·도구 UA
🔴 185.220.101.5 점수 14 — 인증거부 6회·도구 UA
🔴 141.98.80.1   점수 11 — 탐침경로 3개·도구 UA (09:05~09:48, 느린 분산)
정상 브라우저 IP 는 경보 없음(오탐 0)
```

## 로드맵

- v0 ✅ nginx/apache 로그 → P1~P5 탐지 (현재)
- v1 설정 파일(문턱·탐침경로·도구 UA) · apache/공통 포맷 · 정기 자동 실행(--watch) · 알림(파일/webhook)
- v2 드롭인 미들웨어 어댑터(FastAPI/Flask/Express) → 계정 신호·AI 엔드포인트
- v3(선택) 막기(fail2ban 연동) · 대시보드

## 설계 원칙

- 읽기 전용 · 대상 코드 미수정 · 정상 소음 제외(오탐 관리) · stdlib 만으로 동작(의존성 0).

출발점 : INFOLINK 보안 과제에서 만든 침입 감지 규칙(R1~R7)을 로그 기반·프로젝트 독립으로 이식.
